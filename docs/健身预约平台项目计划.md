## 1. 项目概述

一套"健身/生活服务预约"业务，两个端，共用同一套数据：

| 项目 | 名称 | 端 | 技术栈 |
|---|---|---|---|
| 项目一 | 乐享健身预约管理平台 | Web 管理后台 | Vue3 + Vite + Pinia + Vue Router + Element Plus + ECharts + Express + SQLite |
| 项目二 | 乐享健身会员端 | 小程序 | uni-app + Vue3 + Pinia（微信小程序 / H5 多端） |

### 1.1 目录结构

```
lexiang-fitness-booking/  # 项目根；本地运行，源码公开发布到 GitHub
├── server\          # Express + better-sqlite3 后端（端口 3000，全局 CORS）
│   ├── src\db\          # 建表 + 种子数据
│   ├── src\routes\      # 按模块路由
│   ├── src\middleware\  # JWT 鉴权 / 错误处理
│   ├── uploads\         # 课程图片上传（express.static 托管）
│   └── scripts\smoke-test.js   # 一键验证全部接口
├── admin-web\       # Vue3 管理后台（Vite 4180，proxy /api → 3000；原 5180 落入 Windows 端口排除范围 5147-5246 报 EACCES 故改 4180）
└── miniapp\         # uni-app 会员端（H5 4174 / 微信小程序双端）
```

## 2. 总体架构

```
浏览器(后台) ──┐
              ├── HTTP/JSON ──▶ Express 服务（localhost:3000）
小程序/H5 ────┘                        │ 读写
                                       ▼
                                  data.db（SQLite 文件）
```

- 后台前端：Vite dev server（4180，strictPort 固定；原 5180 与 miniapp H5 的 5174 均落入 Windows 端口排除范围 5147-5246 报 EACCES，故分别改为 4180 / 4174），通过 Vite proxy 代理到 3000，解决跨域
- 后端：Express + SQLite（better-sqlite3，已实测 Node 24 可正常安装使用），提供 RESTful 接口，全局开启 CORS（小程序 H5 端直接跨域访问）
- 小程序：uni-app 通过 request 直连后端接口

## 5. 业务规则

### 5.1 预约状态机

```
会员提交预约 → confirmed（服务端事务内校验）
confirmed ──会员取消（开课前 2 小时内禁止）──→ cancelled
confirmed ──后台取消────────────────────────→ cancelled
confirmed + booking_date < 今天 ──查询时自动判定──→ completed（无定时任务）
```

- **名额校验**：该日期该排班 confirmed 数 < capacity 才可提交；校验 + 写入在同一事务内完成，防止并发超卖
- **冲突校验**：同会员同排班同日唯一（UNIQUE 约束）；同教练同时段唯一（UNIQUE 约束）
- **规则校验**：只能预约未来 advance_days 天内；每会员每日预约数 ≤ daily_limit
- **会员状态校验**：停用会员不可提交预约

### 5.2 保护规则

- 已有 confirmed 预约的排班禁止删除（提示先处理预约）；可改为 inactive 停用
- 课程下架 / 教练停用不影响已有预约
- 会员停用后：不可新预约，已有预约保留

### 5.3 登录与鉴权

- 后台：账号密码登录（bcrypt 校验），JWT payload 含 `{ id, role: 'admin'|'staff', type: 'admin' }`
- 会员端：手机号 + 验证码（**模拟固定 123456**，首次登录自动注册 member），JWT payload 含 `{ id, role: 'member', type: 'member' }`
- 两端共用同一 secret 与验签中间件，按 `type` 区分校验角色；无效/过期 token 返回 401
- 前端：后台 axios 拦截器注入 Authorization + 401 统一跳登录；小程序 request 封装同理，token 持久化

## 6. API 接口清单

统一前缀 `/api`，响应格式 `{ code: 0, data, message }`（code 0 成功，非 0 失败）。鉴权：`[公开]` 无需 token；`[admin]` 需后台账号 token；`[member]` 需会员 token。

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | /api/auth/admin/login | 公开 | 后台账号密码登录，返回 token + 用户信息 |

| POST | /api/auth/member/login | 公开 | 手机号+验证码登录，未注册自动注册，返回 token + 会员信息 |
